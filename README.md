# 국내 주식 관심종목 앱

이든크루 Flutter 신입 개발자 과제 1입니다. Naver 데이터를 이용해 관심종목, 검색, 종목상세 화면을 구현했습니다.

## 실행 방법

- 개발 환경: Flutter 3.44.2 (stable), Dart 3.12.2
- 실행 확인: Windows 11 데스크톱
- 인터넷 연결이 필요합니다. 브라우저 실행은 지원하지 않습니다. 네트워크 요청에 `dart:io`를 사용합니다.
- Android와 iOS에서는 별도로 실행을 확인하지 않았습니다.

```bash
flutter pub get
flutter run -d windows
```

디자인을 비교할 때는 앱의 콘텐츠 영역을 Figma 기준인 393 × 852에 가깝게 맞춥니다. Windows 창 제목 표시줄은 앱 콘텐츠에 포함되지 않습니다.

폰트는 제공된 Noto Sans KR의 Regular, Medium, Bold 파일을 그대로 사용합니다. `pubspec.yaml`에 등록하고 앱 테마에 적용했습니다.

## 구현 범위

| 화면 | 구현 내용 |
| --- | --- |
| 관심 | 종목명·코드·시장·현재가·등락액·등락률, 등락 색상, 새로고침, 스켈레톤, 빈 상태, 정렬 바텀시트 |
| 검색 | 검색 및 입력 지우기, 검색어 하이라이트, 관심 등록·해제, 토스트, 상세 이동, 검색 전·결과 없음 상태 |
| 종목상세 | 헤더와 관심 버튼, 현재가와 등락 방향, 4개 기간 탭, 캔들 차트, 요약 카드, 일별 시세 표 |
| 공통 | 다크 테마, 관심·검색 탭 전환, 세 화면의 관심 상태 동기화 |

필수 기능을 구현하고 수동 동작 확인을 마쳤습니다. 검색은 입력 후 Enter 또는 돋보기 버튼으로 실행합니다.

관심 목록과 정렬 기준의 재실행 후 유지, 최근 검색어, 입력 디바운스, Pull to refresh, 차트 툴팁은 구현하지 않았습니다. 검색 요청 중 로딩 표시를 추가했습니다.

## 구조와 기술 선택

```text
lib/
  main.dart
  data/       API 요청과 일별 HTML 파싱
  model/      종목·검색·시세 모델
  screen/     관심·검색·상세 화면과 하단 탭
  state/      공유 관심종목 상태
  theme/      제공된 디자인 토큰과 테마
  widget/     캔들 차트
assets/
  fonts/      제공된 폰트
  mock/       API 응답 샘플
```

- **상태관리:** `FavoriteStore`를 `ChangeNotifier`로 만들고 같은 인스턴스를 화면에 전달합니다. 공유해야 하는 상태가 관심 목록이므로 별도 상태관리 패키지 없이 변경을 알리도록 했습니다. 검색 결과와 로딩 상태 등 화면 내부 상태는 `StatefulWidget`에서 관리합니다.
- **데이터 처리:** HTTP 요청은 `StockApi`, HTML 파싱은 `DailyPriceParser`로 분리했습니다. 화면에서는 파싱된 모델을 사용합니다.
- **주요 패키지:** `charset_converter`는 EUC-KR 응답 디코딩에, `html`은 일별 시세 표를 파싱하는 데 사용합니다.
- **차트:** `CustomPainter`로 캔들과 꼬리를 그립니다. 필요한 기능이 기간별 OHLC 표시이므로 차트 패키지 없이 구현했습니다. 시가와 종가로 캔들 색을 결정하며, 표는 최신순, 차트는 과거부터 표시합니다.
- **디자인 토큰:** 제공된 색상·간격 토큰과 폰트를 사용합니다. 토큰 값 변경이나 추가는 하지 않았습니다.

## 직접 판단한 처리 방식

### 로딩과 오류

관심 목록에서 처음 시세를 받지 못한 행은 스켈레톤으로 표시합니다. 재조회 중에는 기존 시세를 유지하고, 조회 실패 시 안내 문구와 새로고침을 통해 다시 시도할 수 있도록 했습니다.

검색과 상세 화면은 로딩과 오류 상태를 구분합니다. 검색 결과의 메타데이터 조회만 실패하면 검색 응답으로 해당 종목을 표시하고 안내 메시지를 띄웁니다. 일부 요청 실패 때문에 전체 검색 결과가 사라지는 것을 피하기 위한 처리입니다.

검색어 또는 상세 기간을 바꾸면 요청 번호를 비교하여 이전 응답이 현재 화면을 덮지 않게 했습니다. 이미 전송한 HTTP 요청을 취소하는 방식은 아닙니다.

### 정렬과 관심 상태

현재가순·등락률순은 내림차순, 가나다순은 이름 오름차순입니다. 시세가 없는 종목은 가격·등락률 정렬에서 마지막에 배치합니다. 값이 같거나 둘 다 시세가 없으면 이름으로 정렬합니다.

관심 조회 중 등록·해제가 발생하면 최신 목록을 다시 조회합니다. 늦게 도착한 응답으로 해제한 종목이 다시 목록에 들어가지 않도록 확인합니다. 관심 목록은 메모리에만 보관하므로 앱을 종료하면 초기화됩니다.

### 토스트와 긴 텍스트

관심 등록·해제 토스트는 floating SnackBar로 2초간 표시합니다. 연속으로 누르면 기존 토스트를 제거하고 가장 최근 결과를 표시합니다.

목록의 긴 종목명은 한 줄 말줄임으로 처리합니다. 결과 없음 안내 문구에는 입력한 검색어를 포함하고 줄바꿈을 허용합니다.

### 기간 조회와 캐시

선택한 기간의 시작일까지 일별 페이지를 순서대로 조회합니다. 시작일에 도달하거나 마지막 페이지이면 요청을 멈춥니다. 월 단위로 시작일을 계산하며, 해당 월에 같은 날짜가 없으면 월말을 사용합니다.

동일한 `StockApi` 인스턴스 내에서 종목코드·페이지별 요청과 메타데이터 요청을 재사용합니다. 실패한 요청은 캐시에서 제거해 재시도할 수 있게 했습니다. 디스크 저장이나 만료 시간은 적용하지 않았습니다.

### 시안과의 차이

캔들 두께·간격과 가격 범위는 데이터 개수 및 화면 폭에 맞춰 계산합니다. 차트 높이는 220이며 가격 범위에 여유를 둡니다. 이 때문에 시안의 차트 내부 모양과 다를 수 있습니다.

아이콘은 Flutter Material 아이콘을 사용하고, 토스트는 SnackBar의 기본 등장·퇴장 동작을 사용합니다. 시안의 아이콘 획과 애니메이션까지 동일하게 재현하지는 않았습니다. Windows에서는 모바일 상태 표시줄과 홈 인디케이터를 별도로 그리지 않았습니다.

## 확인 결과

- `flutter analyze`: 코드 정리 후 로컬 터미널에서 완료
- 수동 확인: 관심 정렬·새로고침, 검색·빈 상태·토스트, 관심 상태 동기화, 상세 화면의 기간 탭과 차트·일별 시세
- 자동 테스트: 별도로 작성하지 않았습니다. `test/widget_test.dart`는 스타터 화면을 대상으로 한 기존 예제이며 현재 화면에 맞춰 갱신하지 않았습니다. `flutter test` 통과를 확인한 상태는 아닙니다.

## 막혔던 지점

- **시세 응답 인코딩:** UTF-8로 읽을 때 예외가 발생했습니다. 응답의 Content-Type을 확인한 뒤 바이트를 받아 지정된 문자셋으로 디코딩했습니다. 일별 HTML은 charset이 없으면 EUC-KR을 사용합니다.
- **일별 시세 대신 오류 HTML 수신:** 파싱 규칙만 수정하기 전에 응답 내용을 확인했습니다. 요청의 User-Agent와 Referer를 설정한 뒤 일별 시세 표가 내려오는 것을 확인했습니다.
- **프로젝트 이동 후 빌드 오류:** 이전 경로가 CMake 캐시에 남아 있었습니다. 프로젝트를 영문 경로로 옮긴 뒤 빌드 산출물을 정리하고 다시 실행했습니다.
- **빠른 입력·기간 변경:** 이전 요청이 뒤늦게 끝날 수 있어 요청 번호와 화면의 mounted 상태를 확인하도록 처리했습니다.
