# 국내 주식 관심종목 앱

이든크루 Flutter 신입 개발자 과제 1입니다. Naver 데이터를 이용해 관심종목, 검색, 종목상세 화면을 구현했습니다.

## 실행 방법

- **개발 환경:** Flutter 3.44.2 (stable), Dart 3.12.2
- **확인한 플랫폼과 기기:** Windows 11 데스크톱
- **실행 조건:** 인터넷 연결이 필요합니다. 네트워크 요청에 `dart:io`를 사용하므로 브라우저 실행은 지원하지 않습니다.
- Android와 iOS에서는 별도로 실행을 확인하지 않았습니다.

```bash
flutter pub get
flutter run -d windows
```

디자인 비교 시 앱의 콘텐츠 영역을 Figma 기준인 393 × 852에 가깝게 맞춥니다. Windows 창 제목 표시줄은 콘텐츠 영역에 포함되지 않습니다.

폰트는 기본 제공된 **Noto Sans KR Regular·Medium·Bold**를 그대로 사용합니다. `pubspec.yaml`의 폰트 등록과 앱 테마 적용 방식을 유지했습니다.

## 구현 범위

### 필수 항목 중 완료한 것 / 남은 것

필수 기능 구현과 최종 동작 확인을 완료했습니다. 남은 필수 항목은 없습니다.

| 화면 | 구현 내용 |
| --- | --- |
| 관심 | 종목명·코드·시장·현재가·등락액·등락률, 상승·하락·보합 색상, 새로고침, 스켈레톤, 빈 상태, 정렬 바텀시트 |
| 검색 | 검색과 입력 지우기, 검색어 하이라이트, 관심 등록·해제, 토스트, 상세 이동, 검색 전·결과 없음 상태 |
| 종목상세 | 헤더와 관심 버튼, 현재가와 등락 방향, 4개 기간 탭, 캔들 차트, 요약 카드, 일별 시세 표 |

검색은 입력 후 Enter 또는 돋보기 버튼으로 실행합니다. 상세 화면의 기간을 변경하면 차트와 일별 시세 표에 동일한 기간의 데이터를 표시합니다.

## 기술 선택과 이유

### 상태관리, 폴더 구조, 아키텍처

공유 관심종목 상태는 `FavoriteStore`를 `ChangeNotifier`로 구현하고 동일한 인스턴스를 각 화면에 전달합니다. 공유할 상태가 관심 목록 중심이므로 별도 상태관리 패키지 없이 변경을 알리도록 했습니다.

검색 결과와 로딩 상태 등 화면 내부 상태는 `StatefulWidget`에서 관리합니다. 관심·검색 화면은 `IndexedStack`으로 구성해 탭 전환 시 화면 상태를 유지합니다.

```text
lib/
  main.dart
  data/       API 요청과 일별 HTML 파싱
  model/      종목·검색·시세 모델
  screen/     관심·검색·상세 화면과 하단 탭
  state/      공유 관심종목 상태
  theme/      제공된 디자인 토큰과 테마
  widget/     캔들 차트
```

화면, 공유 상태, 데이터 요청·파싱, 모델을 역할별로 분리했습니다. HTTP 요청은 `StockApi`, 일별 시세 HTML 파싱은 `DailyPriceParser`에서 처리하며 화면은 파싱된 모델을 사용합니다.

### 주요 패키지

- **`charset_converter`:** EUC-KR 등 UTF-8이 아닌 응답을 디코딩하는 데 사용합니다.
- **`html`:** 일별 시세 HTML에서 표와 페이지 정보를 파싱하는 데 사용합니다.

### 차트 처리 방식

`CustomPainter`로 캔들 몸통과 꼬리를 그립니다. 필요한 기능이 기간별 OHLC 표시이므로 외부 차트 패키지 없이 구현했습니다.

캔들 색상은 당일 시가와 종가를 비교해 결정합니다. 일별 시세 표는 최신순으로, 차트는 과거부터 표시합니다.

### 디자인 토큰

제공된 시맨틱 색상·간격 토큰과 폰트를 사용했습니다. 디자인 토큰 값을 변경하거나 추가하지 않았습니다.

## 직접 판단한 부분과 이유

### 토스트 노출 시간과 사라지는 방식

관심 등록·해제 토스트는 floating SnackBar로 2초간 표시하고 기본 등장·퇴장 애니메이션을 사용합니다. 배경색·반경·여백·아이콘 간격에는 제공된 디자인 토큰을 적용했습니다.

연속으로 조작하면 기존 토스트를 제거하고 최신 결과를 표시합니다. 이전 알림이 쌓여 현재 관심 상태와 다른 메시지가 뒤늦게 표시되는 것을 방지하기 위한 처리입니다.

### 로딩 / 네트워크 에러 / 긴 종목명 오버플로

- **관심 목록:** 처음 시세를 받지 못한 행은 스켈레톤으로 표시합니다. 재조회 중에는 기존 시세를 유지하며, 실패하면 안내 문구와 새로고침으로 재시도할 수 있게 했습니다.
- **검색·상세:** 로딩과 오류 상태를 구분하고 재시도 수단을 제공합니다. 검색 결과의 메타데이터 조회만 실패하면 검색 응답으로 종목을 표시해 일부 실패로 전체 결과가 사라지지 않게 했습니다.
- **긴 텍스트:** 긴 종목명은 한 줄 말줄임으로 처리합니다. 검색 결과 없음 문구에는 입력한 검색어를 그대로 포함하고 줄바꿈을 허용합니다.
- **이전 응답 처리:** 검색어 또는 상세 기간 변경 시 요청 번호를 비교해 이전 응답이 현재 화면을 덮지 않게 했습니다. 이미 전송한 HTTP 요청을 취소하는 방식은 아닙니다.

### 시세를 못 받은 행의 정렬

현재가순·등락률순은 내림차순, 가나다순은 이름 오름차순입니다.

시세가 없는 종목은 현재가순·등락률순에서 마지막에 배치해 비교 가능한 종목을 먼저 보여줍니다. 값이 같거나 둘 다 시세가 없으면 이름으로 정렬합니다.

### 기간 조회와 캐시

선택한 기간의 시작일까지 일별 페이지를 순서대로 조회합니다. 시작일에 도달하거나 마지막 페이지이면 요청을 멈춥니다. 시작일은 월 단위로 계산하며 해당 월에 같은 날짜가 없으면 월말을 사용합니다.

일별 시세와 메타데이터 요청은 각 화면이 사용하는 `StockApi` 인스턴스 안에서 재사용합니다. 상세 화면에서 기간을 변경하면 이미 조회한 페이지를 재사용하고, 상세 화면에 새로 진입하면 캐시도 새로 생성됩니다.

실패한 요청은 캐시에서 제거해 재시도할 수 있게 했습니다. 디스크 저장과 만료 시간은 적용하지 않았으며, 현재 시세는 캐시하지 않아 새로고침 시 다시 요청합니다.

### Figma와 다르게 구현한 부분

- **차트:** 캔들 두께·간격과 가격 범위를 데이터 개수 및 화면 폭에 맞춰 계산합니다. 차트 높이는 220이며 가격 범위에 여유를 두므로 시안과 차트 내부 모양이 다를 수 있습니다.
- **아이콘과 애니메이션:** Flutter Material 아이콘과 SnackBar 기본 애니메이션을 사용했습니다. 기본 제공 요소를 활용했으며 시안의 아이콘 획과 애니메이션까지 동일하게 재현하지는 않았습니다.
- **시스템 영역:** Windows 데스크톱에서 실행하므로 모바일 상태 표시줄과 홈 인디케이터는 별도로 그리지 않았습니다.

## 막혔던 지점과 어떻게 접근했는지

- **시세 응답 인코딩:** UTF-8로 읽을 때 예외가 발생했습니다. 응답의 Content-Type을 확인한 뒤 바이트를 지정된 문자셋으로 디코딩했습니다. 일별 HTML은 charset이 없으면 EUC-KR을 사용합니다.
- **일별 시세 대신 오류 HTML 수신:** 파싱 규칙을 수정하기 전에 실제 응답 내용을 확인했습니다. 요청에 User-Agent와 Referer를 설정한 뒤 일별 시세 표가 내려오는 것을 확인했습니다.
- **프로젝트 이동 후 빌드 오류:** 이전 경로가 CMake 캐시에 남아 있었습니다. 프로젝트를 영문 경로로 옮기고 빌드 산출물을 정리한 뒤 다시 실행했습니다.
- **빠른 입력·기간 변경:** 이전 요청이 늦게 완료되어 현재 화면에 반영될 수 있었습니다. 요청 번호와 화면의 `mounted` 상태를 확인하도록 처리했습니다.
